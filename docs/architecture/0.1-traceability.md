## Artifact contract

The shareable success artifact is `result.json` with `schemaVersion: "1.0"`.
Its object fields use the following order. Omitted fields and `null` values are
different states.

| Object | Ordered fields |
| --- | --- |
| Artifact | `schemaVersion`, `ticket`, `proofSubject`, `evidencePlan`, `proofRun`, `criterionResults`, `overallStatus`, `proofSeal`, `rerunInputs`, `warnings` |
| `ticket` | `tracker`, `url`, `owner`, `repository`, `number`, `title`, `criteria` |
| `ticket.criteria[]` | `id`, `text`, `checked`, `nesting`, `raw` |
| `proofSubject` | `criteriaHash`, `codeFingerprint` |
| `codeFingerprint` | `commitSha`, `trackedPatchSha256`, `dirtyFiles`, `untrackedFiles`, `lockfile`, `completeness`, `digest` |
| `dirtyFiles[]` | `path`, `status` |
| `untrackedFiles[]` | `path`, `size`, `sha256` |
| `lockfile` | `path`, `sha256` |
| `evidencePlan` | `hash`, `approval`, `commands` |
| `evidencePlan.commands[]` | `id`, `command`, `criteria` |
| `command` | `executable`, `args`, `cwd`, `timeoutSeconds`, `environmentPolicy` |
| `environmentPolicy` | `variables`, `inherit` |
| `proofRun` | `executionEnvironment`, `startedAt`, `endedAt`, `durationMs`, `runError`, `commands`, `cleanup` |
| `executionEnvironment` | `os`, `architecture`, `git`, `runtime`, `packageManager` |
| `proofRun.commands[]` | `id`, `command`, `mapping`, `execution`, `output` or `error` |
| `execution` | `state`, `exitCode`, `signal`, `startedAt`, `endedAt`, `durationMs`, `networkPolicy` |
| `output` | `streams`, `warnings` |
| `output.streams.<name>` | Text: `binary`, `byteCount`, `excerpt`, `truncated`. Binary adds `sha256` and sets `excerpt` to `null`. |
| `criterionResults[]` | `id`, `text`, `checked`, `status`, `evidence`, `rationale` |
| `criterionResults[].evidence[]` | `type`, `commandId`, `execution` and `output`, or `error` |
| `rerunInputs` | `issueUrl`, `repository`, `checkoutPath`, `criteriaHash`, `codeFingerprintDigest`, `evidencePlanHash` |
| `rerunInputs.repository` | `owner`, `name` |
| `warnings[]` | `code`, optional `path`, optional `reason`, optional `stream` |

The operation envelope adds `kind: "proof-run"`, the artifact fields, and
`proofCard`. `result.json` is the artifact object, not the operation envelope.

| Field | Allowed values or nullability |
| --- | --- |
| `schemaVersion` | The string `1.0`. |
| `ticket.tracker` | The string `github`. |
| `codeFingerprint.completeness` | `COMPLETE` or `INCOMPLETE`. |
| `evidencePlan.approval` | The string `APPROVED` in a successful artifact. |
| `execution.state` | `EXITED`, `SIGNALED`, or `TIMED_OUT`. |
| `execution.exitCode` | An integer for `EXITED`. `null` for `SIGNALED` and `TIMED_OUT`. |
| `execution.signal` | `null` for `EXITED`. A string for `SIGNALED` and `TIMED_OUT`. |
| `execution.networkPolicy` | The string `DENIED`. |
| `criterionResults[].status` | `PROVED`, `FAILED`, or `UNVERIFIED`. |
| `criterionResults[].evidence[].type` | The string `automated`. |
| `overallStatus` | `PROVED`, `FAILED`, or `INCOMPLETE` on a successful artifact. |
| `proofSeal` | A `sha256-v1:` prefix followed by 64 lowercase hexadecimal characters on a successful artifact. |
| `cleanup.state` | `NOT_REQUIRED`, `CLEANED`, or `FAILED`. |
| `lockfile.path`, `lockfile.sha256` | Both strings for a selected lockfile, or both `null` when absent. |
| `proofRun.runError` | `null` for a successful artifact. |
| `overallStatus`, `proofSeal` on a run error | Both `null`. |

Criteria and criterion results preserve issue source order. Commands and command
evidence preserve approved-plan order. Command mappings preserve their approved
order. Dirty files sort by path and status. Included untracked files sort by
path. Warnings sort by code, reason, path, and stream. Code fingerprint fields
contain repository state only. Execution environment fields belong under
`proofRun.executionEnvironment`.

The proof seal is an explicit allowlist containing `criteriaHash`,
`codeFingerprint`, `evidencePlanHash`, `executionEnvironment`, ordered
`commandOutcomes`, ordered `criterionStatuses`, `overallStatus`, and material
warning codes and values. Each command outcome contains its command ID, stable
approved command, outcome state, exit code or signal, timeout, and network
policy, or its policy code. Output excerpts, output hashes, timestamps,
durations, cleanup, rerun inputs, proof-card formatting, absolute paths,
temporary paths, credential values, and untracked-file content stay outside
the seal.

## Issue #6 composition

The complete public seam is covered by
`test/issue-proof.test.mjs`: clean and tracked-dirty runs, multiple criteria,
approved safe-untracked content, equivalent presentation repeats, stable-fact
seal changes, output masking and limits, binary output, incomplete fingerprints,
policy failures, source mutation, dependency mutation, and cleanup facts. The
compatibility test asserts the ordered shareable field contract and confirms
that dependency and execution-environment details do not leak into the
repository-only code fingerprint.

Issue #9 is closed and its predecessor safety contract is included in the
evidence above. Post-0.1 behavior remains out of scope.
